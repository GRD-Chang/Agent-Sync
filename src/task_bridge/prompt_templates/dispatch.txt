执行要求：
你需要直接自主推进该任务，直到 requirement 达成，或明确进入 blocked/failed。
1. 你已经收到上面的 requirement；同时读取 task.json 和 TOOLS.md，确认任务目标、范围、验收口径、本地工具约束与执行边界。
2. 缺失的代码事实、文件位置或实现细节，优先通过读取仓库、文档、测试和相关文件补齐；只有目标、权限、范围或验收标准无法判断时，才写回明确阻塞原因。
3. 如果 requirement 指定了 repo、worktree、cwd 或工作路径，开始执行前先检查该路径下是否存在 AGENTS.md；如果存在，先阅读并遵守其中规则。
4. 先查看当前会话可用的 skills；如果存在匹配当前任务的 skill，优先使用该 skill 组织执行。没有匹配 skill 时，再直接阅读仓库、运行命令并整理证据。
5. 接到任务后，开始任何实际工作前，必须先通过 task-bridge 将 task 标记为 running。
6. 执行任务时，使用 task-bridge 持续写回 result，记录关键进展、验证证据和当前判断。
7. 如果你希望 team-leader 能查看完整执行细节，请在任务进入 done/blocked/failed 前，将关键执行结果写入 detail_path 指向的 detail.md；内容不限定模板。若该文件存在，bridge 会在通知 team-leader 时附带该路径。
8. 准备结束前，必须对照 requirement 验收结果，明确说明是否满足要求；若不满足，继续修改并再次验证，直到满足 requirement。
9. 验收通过后，如果当前工作目录位于 Git 仓库，且本轮产生了与任务相关的有效修改，先完成一次只包含当前任务相关改动的 commit。
10. commit 完成后，才可以通过 task-bridge 将任务标记为 complete；修改 task 状态必须是最后一步。
11. 最终写回的 result 必须清楚说明：完成了什么、验证证据、是否满足 requirement、风险/限制、以及是否已 commit。
